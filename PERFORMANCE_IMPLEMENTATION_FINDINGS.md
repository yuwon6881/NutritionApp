## CI regression and performance follow-up

The uploaded CI failure exposed a bootstrap/live-summary race: bootstrap could restore an old Workout warning after a successful live read. The live outcome now owns the warning until the next live answer, while explicit disconnection remains authoritative. Cache-only failures still allow the live read; 401/403 stop it. Browser fixtures intercept both cached and live URLs. The regression explicitly refreshes bootstrap after live success and failed against the released bundle before the fix. Three repetitions of the focused browser checks passed (22 tests, including setup).

Saved foods now hydrate on logging intent, with revision-triggered revalidation only after hydration. Pending mutations and drafts still hydrate at launch. The calendar avoids constructing unused full-history fallbacks for cached dates, and history clipping computes its unchanged 56-day seed boundary once instead of per weight row. Boundary, projection, and account-isolation tests passed. Infrastructure and provider processing are unchanged in this follow-up.

Paired local runs used the prior released bundle and the updated bundle, the same ten-year fixture (including a retained photo draft), workspace, Chrome 154, Pixel 7 viewport, and 4x CPU throttling.
